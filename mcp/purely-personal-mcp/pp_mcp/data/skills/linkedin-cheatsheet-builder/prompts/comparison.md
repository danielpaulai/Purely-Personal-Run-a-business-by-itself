## FORMAT SELECTION GUIDE

### FORMAT 1: "X vs. Y Comparison" (Side-by-Side Analysis)
- **Use when:** Comparing two approaches of equal weight
- **Structure:** 6-8 category rows, 2 comparison columns
- **Example:** "B2B vs. B2C Marketing"

### FORMAT 2: "Bad vs. Good Approach" (Right vs Wrong)
- **Use when:** Showing tactical mistakes vs. correct methods
- **Structure:** 6-8 numbered/labeled rows, Bad vs Good columns
- **Example:** "Bad vs. Good B2B Marketing Strategy"

### FORMAT 3: "What They Think vs. Reality" (Myth-Busting)
- **Use when:** Debunking widespread misconceptions
- **Structure:** 5-7 belief categories, Perception vs Reality columns
- **Example:** "What Founders Think About Scaling vs. The Reality"

## FORMAT 1: X VS. Y COMPARISON (SIDE-BY-SIDE ANALYSIS)

### STRICT STRUCTURE
```
[Title]: [Concept X] vs. [Concept Y] [Optional descriptor]

| Category | [Concept X] | [Concept Y] |
|---|---|---|
| [Category 1] | • [point 1, 8-12 words]<br>• [point 2]<br>• [point 3] | • [point 1]<br>• [point 2]<br>• [point 3] |
| [Category 2] | ... | ... |
[6-8 category rows total]

**Similarities:**
• [3-4 bullets, 10-14 words each]
```

- 2-4 bullet points per cell (3 ideal)
- Each bullet: 8-12 words

## FORMAT 2: BAD VS. GOOD APPROACH (RIGHT VS WRONG)

### STRICT STRUCTURE
```
Bad vs. Good [Topic/Approach Name]

| # | ❌ Bad | ✅ Good |
|---|---|---|
| 1 | [Wrong action, 10-15 words] | [Right action, 10-15 words] |
| 2 | ... | ... |
[6-8 numbered rows]

**Negative Keywords:** #wasteoftime #burnout #lowROI #churn (4-6 negative tags)
**Positive Keywords:** #compounding #pipeline #retention #leverage (4-6 positive tags)
```

## FORMAT 3: WHAT THEY THINK VS. REALITY (MYTH-BUSTING)

### STRICT STRUCTURE
```
What [Target Audience] Think vs. The Reality About [Topic]

| Category | ❌ What They Think | ✅ The Reality |
|---|---|---|
| [Category 1] | [Belief, 10-15 words] | [Truth, 10-15 words] |
| [Category 2] | ... | ... |
[5-7 categories]

**The Bottom Line:** [14-18 words that challenges thinking]
```

## WRITING STANDARDS (ALL FORMATS)

- Vocabulary Grade 3-4 EXCEPT industry tech terms
- Word count flexibility: ±20% per cell when needed for clarity
- Content sources: ONLY from reference context (no invention)
- Comparison quality: every row must show genuine difference, not synonym swap
- Visual structure: designer-ready table, no extra commentary

## FORBIDDEN PATTERNS
- ✗ Generic comparisons everyone already knows
- ✗ Strawman "bad" examples nobody actually does
- ✗ Padding rows to hit category count
- ✗ Adjective comparisons ("good vs better")
- ✗ "Pro:" / "Con:" labels (use ❌ ✅ only)
- ✗ Cells over 20 words
- ✗ Multi-column repetition (right column doesn't just say "do the opposite")
- ✗ Industry buzzwords as comparison points

## QUALITY CHECKS (12)
1. Could the client defend every comparison point?
2. Does every row show genuine, non-obvious difference?
3. Are technical terms preserved exactly?
4. Is the title 8-12 words?
5. Are emojis (❌ ✅) consistent throughout?
6. Could a designer paste this straight into Canva?
7. Does Bottom Line / Keywords / Similarities section land the takeaway?
8. Is the target audience explicit in title?
9. Are bullets parallel structure (verbs match verbs)?
10. Is there ZERO repetition between rows?
11. Does the comparison earn the "save" action?
12. Could a competitor publish this exact table? (If yes, it's not specific enough.)

## TECHNICAL TERMS (KEEP)
- ✓ "Firmographic & account-based targeting"
- ✓ "B2B2C partnership models"
- ✓ "Qualified revenue pipeline vs. cheap leads"
- ✓ "ROI, efficiency, and risk mitigation decision drivers"

## WORKFLOW (7 steps)
1. Understand the topic + client positioning
2. Select 6-8 categories appropriate to format
3. Extract concrete points from reference context
4. Write title (8-12 words, target audience explicit)
5. Build the table (rows, cells, parallel structure)
6. Add special closing element (Similarities / Keywords / Bottom Line)
7. QA against all checks

## OUTPUT DELIVERY

Markdown table; checkbox (□) or bullet (•); emoji ❌ ✅; bold category/headers. Optional Design Notes for the designer.
